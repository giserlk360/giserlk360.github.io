坐标系与投影

地球是圆的，屏幕是平的 —— 坐标系是 WebGIS 的第一课

WGS

WGS-84

GPS 标准坐标系

● 国际通用，GPS 设备原始坐标
● Google Earth / OSM 使用
● EPSG:4326 (经纬度)
北京: 116.397, 39.908
GCJ

GCJ-02

国测局坐标系 (火星坐标)

● 中国法规要求使用的加密坐标
● 高德地图 / 腾讯地图 / Google 中国
● 在 WGS84 基础上加偏移
北京: 116.404, 39.915
BD

BD-09

百度坐标系

● 百度在 GCJ-02 上再次加密
● 仅百度地图使用
● 偏移量最大，与其他系不兼容
北京: 116.410, 39.918
CGCS

CGCS2000

2000 国家大地坐标系

● 中国法定国家大地坐标系
● 2008 年起正式启用，替代北京 54 / 西安 80
● EPSG:4490，椭球与 WGS84 极为接近
● 自然资源/国土测绘等领域强制使用
北京: 116.397, 39.908

同一地点，三种坐标 —— 偏移可视化

天安门广场在不同坐标系下的位置差异（放大展示）

WGS-84 (真实位置) GCJ-02 (偏移 ~500m) BD-09 (偏移 ~1km)

EPSG:4326 (经纬度)

等经纬度投影，直接使用经度/纬度，单位：度

// Leaflet 中使用
const map = L.map('map', {
  crs: L.CRS.EPSG4326
});

EPSG:3857 (球面墨卡托)

Web Mercator 投影，单位：米，大多数瓦片服务的标准

// Leaflet 默认
const map = L.map('map');
// crs 默认为 EPSG3857

地图瓦片服务

整张地图太大？切切成小块，按需加载 —— 这就是瓦片

瓦片是怎么工作的？

1 整张地图被预先切割成 256 x 256 像素的小图（瓦片）
2 每一级缩放（zoom level）的瓦片数量是上一级的 4 倍
3 浏览器只加载当前视口内的瓦片，按需请求
4 通过行列号（x, y）和缩放级别（z）定位每个瓦片

瓦片金字塔 (Tile Pyramid)

缩放级别越大，瓦片越多，细节越丰富

注意：坐标转换

使用国产地图 API 时，务必确认坐标系！WGS-84 坐标需要转换为 GCJ-02（高德）或 BD-09（百度）才能正确显示位置。天地图使用 CGCS2000 坐标系（与 WGS-84 几乎一致）。

框架选型指南

根据项目需求选择合适的技术栈

场景 客户使用 ArcGIS Server 发布地图服务

需要对接 MapService / FeatureService，进行空间查询、数据编辑

选型： ArcGIS JS API （原生支持 ArcGIS Server 服务，无需适配）
场景 需要地名地址查询、路径规划

POI 搜索、地址解析、逆地理编码、导航路线

选型： 高德 JS API （地理编码、POI、路线规划等服务开箱即用）
场景 展示一张地图，标注点位，简单交互

加载瓦片底图 + GeoJSON 边界 + 标记点 + 弹窗，没有复杂 GIS 需求

选型： Leaflet （轻量 ~40KB，上手快，插件丰富，大多数 2D 项目首选）
场景 需要对接多种 OGC 标准服务

WMS / WFS / WCS 多种服务，自定义投影，需要完整的 GIS 功能

选型： OpenLayers （原生支持 OGC 全家桶，任意投影，企业级首选）
场景 需要三维地球、数字孪生

加载 3D Tiles 建筑模型、地形数据，实现三维场景浏览与模拟

选型： Cesium （3D Tiles 标准制定者，三维地球领域的绝对主力）
场景 需要精美的地图可视化风格

数据大屏展示，自定义地图样式，矢量瓦片渲染，流畅交互

选型： Mapbox GL JS （矢量瓦片极致渲染，样式定制能力最强）
场景 政务项目，需要权威底图数据

CGCS2000 坐标系，国产合规，免费可用的影像和矢量底图

选型： 天地图 + Leaflet/OL （国家平台，免费开发者 Key，可作为任意框架底图）
场景 快速出原型，项目不确定用什么框架

先跑通地图功能，后续再按需切换，或者项目本身就是简单展示

选型： Leaflet （最容易上手，API 简洁，社区活跃，80% 的 2D 需求都能满足）

开发注意事项

实际开发中容易踩的坑，提前了解避免浪费时间

禁止 第三方渲染库实例禁止用 Vue ref/reactive 包裹

地图（Leaflet、Mapbox、Cesium）、图表（ECharts、D3）、三维引擎（Three.js）等第三方库的实例对象，一律用普通变量定义。这些库自行管理 DOM 渲染，Vue 的响应式代理（Proxy）只会带来无谓的性能开销和不可预期的副作用。

❌ 错误写法
import { ref, onMounted } from 'vue'
import L from 'leaflet'

const map = ref(null)  // ❌ 被代理，性能浪费
onMounted(() => {
  map.value = L.map('map-container')
})
✅ 正确写法
import { onMounted } from 'vue'
import L from 'leaflet'

let map = null  // ✅ 普通变量
onMounted(() => {
  map = L.map('map-container')
})

前沿技术与发展趋势

WebGIS 在不断演进，关注前沿方向

趋势 WebGPU 渲染

新一代 Web 图形 API，大幅提升海量地理要素的渲染性能，未来将逐步取代 WebGL

趋势 AI + GIS

趋势 数字孪生

趋势 云端一体化
